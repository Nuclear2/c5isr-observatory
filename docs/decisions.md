# 设计决策记录

## ADR-001：采用 Rust 模块化单体

日期：2026-10-22。状态：采用。

用户倾向 Rust，领域内核又需要清晰的状态约束与可复现行为，因此内核和服务都使用 Rust。Axum/Tokio 处理本地 API 与调度，React/TypeScript 处理显示。暂不引入 Kafka、微服务、容器编排或分布式数据库。成本是两套 DTO 需要协调，目前以共享契约和验收测试约束。

## ADR-002：展示身份和合成行为分开

日期：2026-10-22。状态：采用。

保留用户要求的装备型号与类型标签；所有实验参数是自定义合成值，场景为虚构网格。未确认名称标为概念符号。模型桥接再将对象匿名化，只提供信息质量与网络状态。增加型号不意味着添加真实能力模型。

## ADR-003：模型提出建议，内核执行状态转移

日期：2026-10-22。状态：采用。

模型只能返回固定四类任务的 JSON。桥接校验结构及引用，内核再次校验动作、对象、证据时效、重复项与当前状态；人工模式由人批准，显式启用的 AI 信息模式只自动批准本轮新增且验证通过的模型建议，再在仿真步执行。模型错误不会转为规则结果冒充成功。外部模型延迟不会阻塞暂停入口。

## ADR-004：用官方 Codex CLI 接入已有订阅

日期：2026-10-22。状态：采用。

用户明确希望利用 ChatGPT 订阅。官方 Codex CLI 支持订阅登录和非交互结构化输出；本项目通过子进程调用该入口，保留官方认证流程，不建立私有 API 代理、不提取认证令牌、不切换到 API 计费。调用由人手动触发或由用户显式启用的 AI 信息模式安排，一次一个，有超时与输出限制。CLI 和可用模型可能升级，故集中封装于一个适配文件并提供离线协议测试。

## ADR-006：我方已接收信息视角

日期：2026-10-22。状态：采用，替代初版全节点导演视图。

隐藏环境与可见接触分开，扫描、传输、接收是不同状态；API不输出未发现对象，前端无需自行隐藏真值。接触显示最后收到的报告位置，48步未刷新后过期归档。感知周期控制发现节奏，不能当作真实探测率或OODA效率；没有目标被打击后消失的状态。

## ADR-007：用户启用的连续 AI 信息任务

日期：2026-10-22。状态：采用，更新 ADR-003/004 原先仅人工触发的约束。

用户要求连续接管，因此提供人工与AI信息模式。权限范围仍为本方四类信息任务，模型上下文不加入接触位置或身份。调用最小间隔60秒、单请求互斥，等待模型时保持仿真时钟。停止会取消当前子进程并丢弃迟到结果；错误停止且不自动重试。默认人工模式，刷新页面读取服务现状，服务重启回人工，不会隐式消耗订阅用量。代价是模型耗时期间动画与仿真推进暂停，以及不提供目标选择或自动攻击。

## ADR-005：首版回放为快照回看

日期：2026-10-22。状态：采用。

首版保留最近 360 个节点/链路/指标快照，时间轴只读显示历史帧，实时命令在回看期间禁用。JSON 导出保存当前滚动数据、命令日志与模型最终结果。它不是完整事件存储，也没有导入恢复。完整归档需要保存被淘汰的证据、版本化场景与输入输出，列为后续独立工作。
